# tests

Checks for the Grup-Al Jüri page and the grupal-proxy edge function. They live in the repo on purpose: the sandbox that held the previous suite was wiped (23.09.2026).

- `grupal.test.js` — jsdom checks (phone deck, desktop grid/sidebar/drawer, filters, resize, lobby, v10a Grup-Al / Hemen-Al lanes, invitation sheet, table line, guest `?d=` banner).
- `mock-meydan.json` — a `/meydan` fixture (24 coffees, 18 kapora on 9). Lane fixtures (`hemen`, `img_url`) are added in-test.
- `admin.test.js` — jsdom checks of the admin's Düzenle link resolution (v30d `cartLinkFrom`: cart permalink pass-through, `?variant=` conversion, proxy `/admin/variants` pick, select fallback, old-proxy alert).
- `shot-overlay.mjs` — desktop 1366: opening a card overlays the card below; asserts no card moved, the panel extends beyond the 400 px cell, and a click on empty space closes it (v10p).
- `shot-gate.mjs` — phone shots of the one-time WhatsApp gate (first Kapora koy → sheet → Devam → kapora continues; bind sheet).
- `shot-tickets.mjs` — phone (390 × `VH`, default 900) shots of the five ticket states on the real page: no kapora · kapora in basket (ghost ticket) · paid holder (Gönder / Masaya bırak) · used + on table (geri al) · stranger with a table seat.
- `shot-lanes-desk.mjs` — desktop grid card with both lanes open at 1366 and 1728 px; asserts the lanes sit side by side without overflow (v10g).
- `shot-desk.mjs` — Playwright screenshots at 1366 and 390 px, three themes.
- `shot-lanes.mjs` — Playwright screenshots of the two-price card, the lanes sheet (open / sold out), the invitation sheet and the guest banner.
- `proxy-harness.mjs` + `proxy.test.mjs` — the proxy `.ts` transpiled with `typescript` and run against an in-memory PostgREST (settings / offers / votes tables) with a fake `Deno`; covers the Hemen-Al lane, pool, invitations, table, counting toward 40, limits, expiry, admin settings, `/hemen-link` discount codes, `/admin/variants`, `/admin/inv-backfill`, jury gate (member = order, `/wa-ok`, `/dev-bind`, device merge, `/admin/users`; the dormant `/auth/*` OTP routes), forced lock (`/admin/offer-lock`), completion codes (`/done-link`), members backfill. Point `PROXY=` at the `.ts` (default `../proxy/proxy.ts`; the delivered copy is `deliver-grupal-proxy-function-v3_48.ts` in the CoffeeNutz folder).

Run from the repo root (once: `npm i -D jsdom playwright-core typescript` somewhere and point NODE_PATH at it; ESM files need a `node_modules` link next to the repo):

    NODE_PATH=/path/to/node_modules node tests/grupal.test.js
    NODE_PATH=/path/to/node_modules node tests/admin.test.js
    node tests/middleware.test.mjs
    PROXY=/path/to/deliver-grupal-proxy-function-v3_48.ts node tests/proxy.test.mjs
    node tests/shot-desk.mjs && node tests/shot-lanes.mjs

## v11m (2026-10-02) — PayTR paid, Shopify never made the order → "Sipariş eşle"
- **Incident**: PayTR charged 825 TL (Burçin, El Recreo Tamamla ×1 + kargo) but PayTR's "paid" notification never resolved Shopify's checkout → Orders → Abandoned checkouts, no order, no webhook, no proxy row. Fixed by hand: Shopify "Create order" + Mark as paid, then one SQL UPDATE on her vote row (`done_order` = the Shopify order id). The proxy's webhook ignores a hand-made order (no cart attributes) — hence the new admin flow.
- **Proxy v3.55**: `POST /admin/order-mark {kind: kapora|done|hemen, offer, order_id, email|dev, qty?, inv?, name?}` builds a paid-order payload with the cart attributes and dispatches it through the real `/shopify-hook` path (signed with the webhook secret), so the row / invitations / member record are exactly what the webhook would have written. Guards: digits-only order id, `done` needs a member or dev, a locked coffee and an unfinished converted kapora (409 `notlocked` / `nomatch` / `already`), duplicates → `reason dup`. `GET /admin/links-open` lists the last 7 days of `/done-link` (`dl_`) and `/hemen-link` (`hl_`) records with member, coffee, packages, total and state `ok` (order arrived) / `wait` / `missing` (expired, no order → check PayTR) / `x` (dismissed via `POST /admin/link-dismiss {code, undo?}`). `hl_` records now carry `qty` and `total`, `dl_` carry `total`; `dl_` is swept with the rest after 14 days. The `Deno.serve` handler is named (`handle`) so the admin route can call it recursively.
- **Admin v2026-10-02a**: "Sipariş eşle" section under Jüri üyeleri — the links list (sipariş yok / bekliyor / ✓ sipariş geldi / yok sayıldı, with `Eşle…` prefill and `yok say` / `geri al`) and the form (tür · kahve · e-posta · Shopify sipariş id · paket · davetiye) → `Eşle ve say`. `tests/admin.test.js` covers rendering, prefill, validation, the POST bodies and the error mapping; `tests/shot-admin-links.mjs` renders the card.

## v11q (2026-10-03) — Hemen-Al basket: several coffees, one cart · proxy v3.58
- **Was**: every `Sepete git` built a new Shopify cart link for that one coffee with a product-locked single-use code; a second coffee replaced the first.
- **Now**: the page keeps a Hemen-Al basket (`grupal_hbasket`, items expire with the code after 2 h). `Sepete git` adds the coffee and sends ONE `/hemen-link {items:[{id,qty,inv}]}` for everything in the basket; proxy v3.58 checks each coffee's rules (pool / invitation / green), mints one code covering all those products for the summed amount, and returns `/cart/V1:q1,V2:q2?discount=…&attributes[offers]=id:q,…&attributes[hemen]=1(&attributes[inv]=…)`. The webhook's Hemen-Al path turns the `offers` list into one H/I row per coffee (one order, counted per coffee; invitations consumed per coffee). A bottom bar "⚡ Hemen-Al sepeti · n kahve · m paket · total" (names, Temizle, Sepete git) shows what the Shopify cart will contain; the other coffee's lane says "+ sepette: …". A coffee that stops passing (full/expired…) is dropped with a toast and the link retried once; a paid coffee leaves the basket when `/offer-mine` reports its row.
- Side fix found on the way: in `offLoadMine` an inline `//` comment had swallowed `BANNED=j.banned_until…` — the ban from admin never reached the page. Fixed with block comments; tests guard it.
